# Genshin Impact module

- Module ID: `genshin-impact`.
- Scope: Genshin Impact only.
- Follow [games/AGENTS.md](../AGENTS.md) and the root data-safety rules.
- Keep Genshin-specific entity types, relations, fields, event sources, parsers, fixtures, migrations, and custom UI in this module.
- Do not assume an API, RSS feed, entity taxonomy, region schedule, or time zone until it is documented from a confirmed source.
- Shared HoYoverse helpers are allowed only for behavior proven common; do not depend directly on the Honkai: Star Rail module.
- Confirmed source boundary checked on 2026-08-24: the official [global character directory](https://genshin.hoyoverse.com/en/character/mondstadt) loads its regional catalogs from HoYoverse's public website content service. The official site bundle declares app ID `32`, content key `a1b1f9d3315447cc`, detail channel `407`, and region channels `403`, `404`, `405`, `406`, `653`, `934`, and `1221` for Mondstadt through Snezhnaya. These are website content identifiers, not a general game-data or player-account API.
- The curated [`data/characters.json`](data/characters.json) snapshot contains the 118 records returned by those seven official regional channels on 2026-08-24. Preserve each `official_content_id` and `source_key` across additive refreshes. English is the catalog anchor; Traditional Chinese and Vietnamese records join by the same official content ID. Missing localizations must remain explicit `locale_gaps` rather than falling back silently.
- The global directory supports official Traditional Chinese (`zh-tw`), not Simplified Chinese (`zh-cn`). Never store the Traditional Chinese value as `official_original_name`, automatically convert it to Simplified Chinese, or otherwise present it as the original mainland localization. A future Simplified Chinese source must be separately confirmed and provenance-labeled.
- The fully covered [`data/character-han-viet.json`](data/character-han-viet.json) snapshot contains one generated Hán-Việt search alias for each of the 118 official Traditional Chinese character names, checked on 2026-08-25. Preserve its confidence E label, exact source-name alignment, explicit fallback evidence, and generated-not-official distinction. Never copy these aliases into the official Vietnamese field or present `zh-Hant` as the original mainland name.
- Run [`scripts/fetch-character-han-viet.py`](scripts/fetch-character-han-viet.py) only after reviewing a refreshed character catalog. It sends only the public Traditional Chinese names to the allowlisted Thi Viện transcription endpoint, bounds retries/timeouts/response size, validates complete round-trip coverage, writes atomically, and never opens SQLite.
- Run [`scripts/fetch-characters.py`](scripts/fetch-characters.py) to refresh the reviewable JSON snapshot. The fetcher validates untrusted responses, paginates, bounds timeouts/retries/response sizes, joins locales by content ID, writes atomically, and refuses to shrink an existing catalog unless `--allow-shrink` is explicit after review. It never opens SQLite.
- Run [`scripts/fetch-character-thumbnails.py`](scripts/fetch-character-thumbnails.py) to fill `assets/characters/` from the snapshot's first-party HoYoverse URLs. The downloader allowlists hosts, validates filenames and image signatures, bounds concurrency and response size, and never overwrites an existing valid asset.
- The reviewable [`data/weapons.json`](data/weapons.json) snapshot contains 246 obtainable catalog weapons from pinned `genshin-db` commit `8b15995fa220c88a4d0d7ffe1e21b041d0b32588`; three non-obtainable duplicate Prized Isshin Blade quest variants are explicitly excluded. Treat GenshinData/genshin-db as community-distributed game-data extracts, not an official API. Preserve game-data IDs, source keys, locale provenance, snapshot commit, and the explicit exclusion count.
- The fully covered [`data/weapon-han-viet.json`](data/weapon-han-viet.json) snapshot contains generated confidence-E Hán-Việt aliases transcribed from each weapon's original Simplified Chinese name. Keep them separate from official Vietnamese localization, preserve source-name alignment and fallback evidence, and never promote generated readings to official text.
- [`data/weapon-thumbnails-hoyowiki.json`](data/weapon-thumbnails-hoyowiki.json) is the official-wiki presentation-source boundary. Its 2026-08-26 snapshot matches 245 catalog weapons by English name after only Unicode normalization, apostrophe normalization, and removal of enclosing decorative double quotes. The sole explicit gap is Exaiphanes Blade (`genshin-data-weapon-11521`), which HoYoWiki does not yet list. Do not claim its fallback icon came from HoYoWiki.
- Weapon `ascension_region` is derived from the first weapon-ascension material family. It is a material-domain classification, not lore-origin evidence. The module groups Nod-Krai and Far North material families under its broad `Snezhnaya` region taxonomy; do not present this facet as a weapon's nation of manufacture or story origin.
- Run [`scripts/fetch-weapons.py`](scripts/fetch-weapons.py) against a reviewed, pinned genshin-db checkout. It validates all requested filter fields and localized joins, writes atomically, refuses unexpected shrinkage, and never opens SQLite. Run [`scripts/fetch-weapon-thumbnails.py`](scripts/fetch-weapon-thumbnails.py) to maintain the complete fallback asset set, then [`scripts/fetch-hoyowiki-weapon-thumbnails.py`](scripts/fetch-hoyowiki-weapon-thumbnails.py) for the separate official-wiki primary set. Both validate remote boundaries and never overwrite a valid local PNG. Run [`scripts/fetch-weapon-han-viet.py`](scripts/fetch-weapon-han-viet.py) only after reviewing catalog changes; it never opens SQLite.
- The runtime module exposes the source-confirmed `Character` and extracted `Weapon` types plus the required shared `NPC` and `Region` types. It supplies semantic presentation tokens and is registered by the CLI and UAT composition roots.
- [`data/npcs.json`](data/npcs.json) is a reviewable community-wiki snapshot of 4,967 named NPC/person pages checked on 2026-08-27. It preserves Simplified/Traditional Chinese and Vietnamese page fields when present, infobox regions and locations, page categories, and 2,683 explicit source-backed quest/event/action relationships. The relationship list is intentionally conservative: it uses explicit templates, selected categories, and explicit linked titles rather than inferring appearances from arbitrary prose.
- NPC imports use the shared normalized entity-context tables. One NPC can have many region/location rows and many related quests/events/actions; these rows are source-keyed and additive. The module does not place the relationship list in `other_information`, and it does not treat a category or page mention as proof of a chronological appearance.
- [`data/npc-han-viet.json`](data/npc-han-viet.json) contains generated confidence-E Hán-Việt aliases for the reviewed subset with Chinese names. The snapshot keeps unresolved characters and missing Chinese names explicit; generated readings are search aids, never official Vietnamese translations. Refresh after reviewing the NPC catalog and preserve its coverage gaps.
- Character imports use the core's additive sourced-entity transaction with provider/source identity keys. Repeat imports never replace an existing entity, preserving personal edits. Store official Traditional Chinese as a provenance-labeled `zh-Hant` alias. Until a confirmed Simplified Chinese source exists, repeat the official English catalog anchor in the schema-required original-name field and state that limitation in `other_information`.
- Module-owned Character presentation resolves the stable HoYoverse source key to the bundled local PNG, source-confirmed region facet, bundled local region emblem, and the fully covered [`data/character-presentation.json`](data/character-presentation.json) rarity snapshot. Keep 4-star purple and 5-star gold borders distinct. Aloy remains a 5-star Character but uses the red collaboration border backed by the official HoYoverse support article recorded in that snapshot. Keep rarity in the thumbnail badge. Render region as its monochrome emblem in the right-side context beside the Character type, preserve the region name as accessible text and a load-error fallback, and never put region text or icon over the portrait. Keep exact emblem provenance and checksums in [`assets/regions/README.md`](assets/regions/README.md); the region-emblem catalog is presentation evidence only. Unknown or malformed source keys must return no presentation metadata and must never become filesystem paths.
- Weapon imports are additive and source-keyed. They store Simplified Chinese as the original name, Vietnamese in the official Vietnamese field, Traditional Chinese as a provenance-labeled alias, and generated Hán-Việt as a separate confidence-E alias. Presentation prefers the official HoYoWiki icon and falls back only for an explicit snapshot gap. It owns the five rarity colors and the `weapon_type`, level-1 Base ATK (`main_stat`), `substat`, and `ascension_region` facets. Generic UI rarity filtering and sorting consumes the module's rarity metadata.
- The reviewable [`data/skins.json`](data/skins.json) snapshot contains the 29 non-default entries in the official HoYoWiki Outfit catalog checked on 2026-08-26 and joins pinned multilingual `genshin-db` outfit data. Preserve HoYoWiki entry IDs, grouped multi-character applicability, rarity, and source-key identity. The current source confirms Character outfits only; do not invent weapon or weapon-type Skin records. Keep those reserved applicability fields empty until a source confirms them.
- Skin imports are additive and source-keyed. Keep Simplified Chinese as the original name, official Vietnamese in its dedicated field, Traditional Chinese as an official-localization alias, and [`data/skin-han-viet.json`](data/skin-han-viet.json) readings as separate confidence-E generated aliases. Run [`scripts/fetch-skin-thumbnails.py`](scripts/fetch-skin-thumbnails.py) only against the reviewed catalog; it accepts PNG/GIF from allowlisted first-party hosts and never overwrites valid local assets.
- Artifact Sets and Artifact Pieces are distinct source-keyed entity types. Preserve parent Set keys, real slot coverage, rarity ranges, official locale fields, and confidence-E Hán-Việt aliases; never flatten the hierarchy or fabricate absent pieces. Artifact Domains are grouped by stable entrance ID, while their difficulty stages remain nested metadata. Preserve hosted-Set source-key links and keep Domain region taxonomy title-owned.
- Run the Artifact/Domain snapshot scripts before either importer. The crawlers never open SQLite; the Rust importers are additive and idempotent. Artifact thumbnails must remain local, first-party, host-validated assets and use the maximum available rarity for generic filtering and border color.
- The reviewable [`data/regions.json`](data/regions.json) snapshot contains one world anchor, nine top-level Regions, and 207 Geography Archive-backed subregions joined across English, Simplified Chinese, Traditional Chinese, and Vietnamese at pinned `genshin-db` commit `8b15995fa220c88a4d0d7ffe1e21b041d0b32588`. Preserve stable region/area IDs, parent source keys, duplicate display names, exclusion counts, and the documented Nod-Krai → Snezhnaya relationship. Do not claim the snapshot covers every map label.
- Region imports are additive and source-keyed. Store Simplified Chinese as the original name, official Vietnamese in its dedicated field, Traditional Chinese as an official-localization alias, and [`data/region-han-viet.json`](data/region-han-viet.json) values only as confidence-E generated aliases. Keep `region_type` and `parent_region` title-owned. Run [`scripts/fetch-regions.py`](scripts/fetch-regions.py) before [`scripts/fetch-region-han-viet.py`](scripts/fetch-region-han-viet.py); both write reviewable snapshots and never open SQLite. Preserve explicit `峠` and `哐` fallback evidence unless a stronger reviewed reading replaces it.
- [`data/events.json`](data/events.json) is a reviewed 109-record schedule snapshot covering Version 6.3 (Luna IV) through Version 7.0. Historical windows are sourced from the community-maintained Genshin Impact Wiki event history; current and foreseeable Version 7.0 windows use official HoYoLAB notices. Keep the source boundary and checked date explicit, preserve null end dates for permanent/current records, and do not present this snapshot as live polling.
- Event imports are additive and source-keyed. Event entities use the shared `event` type, while calendar rows retain date/all-day status, event type, patch metadata, source provenance, and optional featured Character keys. Keep Character Wish and Test Run featured keys aligned with the Character snapshot so local thumbnails and previous-banner gap metadata remain resolvable. Do not infer future schedules from an RSS publication timestamp or invent dates when a source is open-ended.
- [`data/books.json`](data/books.json), [`data/quests.json`](data/quests.json), and [`data/lore.json`](data/lore.json) are the 2026-09-02 connected snapshots of 47 Books/book collections, 2,545 Quest/quest-like records, and their source-backed lore graph. The Books category's terminology/index page is excluded from the entity count. The crawler keeps explicit Book↔Quest links, Quest↔Character/NPC links, predecessor/successor relations, redirect aliases, and release-version ordering anchors separate from unknown in-world dates. The strict crawl ended with zero unresolved cross-catalog links; unknown entity names remain provisional subjects rather than fabricated catalog identities.
- Book, Quest, and lore imports are additive and idempotent. Quest links also populate normalized source-backed context rows for Characters, NPCs, and Books, while `Capability::LoreTimeline` exposes the reviewed batch through the shared lore graph. The crawler never opens SQLite; refresh it only after checking the cited community-wiki category pages. Automatic live feed/polling remains intentionally unimplemented.
