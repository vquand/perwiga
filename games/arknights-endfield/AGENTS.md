# Arknights: Endfield module

- Module ID: `arknights-endfield`.
- Scope: Arknights: Endfield only.
- Follow [games/AGENTS.md](../AGENTS.md) and the root data-safety rules.
- Use the project-local [`$curate-endfield-names`](../../.agents/skills/curate-endfield-names/SKILL.md) skill for Endfield multilingual naming research, normalization, reverse lookup, and database imports or upserts.
- Keep Endfield-specific entity types, relations, fields, event sources, parsers, fixtures, migrations, and custom UI in this module.
- Do not assume an API, RSS feed, entity taxonomy, server schedule, or time zone until it is documented from a confirmed source.
- The module exposes `operator`, `npc`, `region`, `weapon`, `enemy`, `mission`, `event`, `item`, `gear-set`, and `essence` entity keys. The common multilingual fields and stable references remain in the shared core; no Endfield-specific fields or namespaced tables are needed yet.
- The module exposes a dark graphite theme with an acid-green accent through semantic theme tokens. Shared UI and a future desktop shell consume these tokens without Endfield conditionals.
- Confirmed source boundaries checked through 2026-08-24 include the official [operator directory](https://endfield.gryphline.com/en-us/operator) and official version notices such as [Homecoming](https://endfield.gryphline.com/en-us/news/5200). These sources confirm operator, weapon, enemy, area, mission, event/activity, item, and NPC terminology. Entity pages remain provenance references; dated version notices also feed the curated event snapshot described below.
- The curated [`data/operators.json`](data/operators.json) snapshot contains the 33 directory entries verified across official English, Simplified Chinese, and Vietnamese sources, with role/class, element, equippable weapon type, and profile race cross-checked on 2026-08-24. Treat it as module-owned import source data; preserve its source keys and the two distinct Endministrator entries during additive refreshes. Preserve the Endministrator race redaction as `null` rather than inventing a value.
- The curated [`data/npcs.json`](data/npcs.json) snapshot contains an initial 134 named NPC/person records cross-checked against aligned English, Simplified Chinese, and Vietnamese client localization on 2026-08-23. Its community catalog is explicitly incomplete, so preserve the documented scope, confidence grades, unresolved values, generated Hán-Việt provenance, and operator exclusions during additive refreshes.
- The curated [`data/regions.json`](data/regions.json) snapshot contains 43 scoped geography records cross-checked against structured client map, domain, level, settlement, and aligned localization data on 2026-08-23. Preserve its `parent_source_key` hierarchy, subtype and status metadata, generated Hán-Việt provenance, evidence labels, unresolved names, and the distinction between community presentation references and naming evidence during additive refreshes.
- The curated [`data/weapons.json`](data/weapons.json) snapshot contains 77 current weapons cross-checked against structured client weapon/item data, aligned English, Simplified Chinese, and Vietnamese localization, first-party version notices, and the community weapon catalog on 2026-08-24. Preserve client weapon IDs, client sort IDs, rarity and weapon-type metadata, exact localized names, generated Hán-Việt provenance, unresolved non-Han names, and the presentation-only status of community icon URLs during additive refreshes.
- The curated [`data/items.json`](data/items.json) snapshot contains 731 current non-weapon records exposed by the client `Database - Item Files` boundary on 2026-08-24. Preserve stable client item IDs, raw item/showing/database group taxonomy, exact localized names, generated Hán-Việt provenance, formula evidence, and the multi-valued `classifications` array during additive refreshes. An Item can belong to any number of normalized classes; never collapse classes such as `collectible`, `consumable`, `craftable`, `crafting-ingredient`, `material`, or `facility` into a single exclusive field.
- The curated [`data/gear-essences.json`](data/gear-essences.json) snapshot contains 23 client-defined Gear Sets and 154 production Essence presets checked on 2026-08-26. Preserve Gear Set membership/effects and all three Essence terms. Never relabel or remove the existing Item/Gear-piece rows. Exclude `gem_test_*` and tutorial-only `gem_guide_*` presets. Persist each official Essence rarity name unchanged; `catalog_label` is a source-composed UI/search label, never an official localization.
- Operator, Weapon, Item, Gear Set, and Essence presentation are module-owned. Curated source keys resolve rarity metadata and embedded local thumbnails; unknown or malformed keys must fall back safely without filesystem access. Operator WebP files originate from the official portrait URLs. Weapon PNG files originate from the snapshot's presentation-only community icon URLs and can be filled non-destructively with `scripts/fetch-weapon-thumbnails.sh`. Item/Essence WebP files originate from client `iconId` values resolved through the indexed extracted-asset host; Gear Sets reuse a member Gear thumbnail. These assets are presentation evidence, not naming evidence. Keep 1-star gray, 2-star green, 3-star slate, 4-star blue, 5-star gold, and 6-star crimson presentation metadata distinct.
- Keep the Endfield Operator role, element, race, optional subrace, and weapon-type vocabularies in this module's facet definitions. The weapon-type vocabulary (`Sword`, `Greatsword`, `Polearm`, `Handcannon`, and `Arts Unit`) applies to both Operators and Weapons. Shared UI may render declared facets generically but must not hard-code these lists or branch on the Endfield module ID.
- Keep Item rarity, non-exclusive type classifications, and optional region metadata in this module. The shared facet contract must preserve all Item classifications rather than collapsing them into one value. Assign `Valley IV` or `Wuling` only where `ItemGatherTextTable.domainId` explicitly resolves through `DomainDataTable`; do not infer a region from the item name, availability in a factory region, or general lore.
- Treat Operator subrace as an optional, explicitly sourced Sarkaz tribe. Do not infer it from appearance, ancestry, a reconvener counterpart, or the broad `Sarkaz` profile value. Current verified values are Liino=`Djall`, Camille=`Vampire`, and Last Rite=`Nachzehrer`; other Operators remain unset until directly attested.
- The curated [`data/events.json`](data/events.json) snapshot contains the Asia-server event history and announced schedule checked on 2026-08-24. Preserve every stable `source_key`, source URL, published start/end value, `Asia server (UTC+8)` semantics, patch span, occurrence index, and scope/provenance note. Do not invent a closing time for permanent activities or events described only as ending before an unannounced version update. Version 1.0 records explicitly labeled as calendar transcriptions use a secondary transcription; version 1.1–1.4 windows use official notices.
- Event-to-Operator previews are module-owned. Use `featured_operator_keys` only for a source-backed relationship, retain a direct relationship source in `featured_operator_source_url` when the schedule notice does not name the Operator, and resolve portraits through the bundled Operator snapshot. Headhunting previews may use rate-up terminology; Narrative previews must use featured-character terminology and must not imply a gacha promotion.
- Limited-banner recency is module-owned and uses only `Headhunting` events with a known end and a source-backed `featured_operator_keys` relationship. Show entity-detail recency only for 6★ Operators. Calculate each preview gap as complete 24-hour days from that Operator's latest preceding banner end to the current banner start, including reruns and group banners; preserve a missing value for a first recorded appearance instead of inventing zero. Narrative associations never count as banners.
- Event import is additive and idempotent by `(work_id, source_provider, source_identity)`. Never refresh the snapshot with replacement, deletion, or a lossy upsert. A new source record may be inserted; correcting an already imported record requires an explicit, independently reviewed data-preserving migration.
- UAT setup imports each curated schedule record into both the universal calendar and the `event` Wiki entity type using the same provider/source identity and the same patch-aware display title. The Wiki copy is additive and preserves the source schedule/provenance without inventing original-language or Vietnamese names; repeated setup must leave both representations unchanged.
- Recurring event display names encode patch ownership in this module: one occurrence uses `Name 1.4`, multiple occurrences fully inside one patch use `Name 1.4.1`, `Name 1.4.2`, and a cross-patch occurrence uses `Name 1.4–1.5`. The shared calendar/timeline must render supplied names and event types generically rather than reproducing these Endfield rules.
- The current scheduled-event capability is a bundled, source-checked snapshot importer, not a live API poller. A future network adapter must separately document refresh cadence, stable remote identity, failure retention, and upstream time-zone behavior before registration.
- The lore map uses the shared candidate-batch contract and the module-owned [`data/lore.json`](data/lore.json) seed. Its four relative periods and five official-publication anchors are intentionally an orientation spine, not a complete game-history claim; setup imports the curated batch through the reviewed path, preserves evidence/source links, and leaves unresolved hear-say subjects provisional. Future LLM-generated batches must remain pending until reviewed.
- Current state: common persistence and manual workflows are implemented, with curated Operator, Weapon, Item, Gear Set, Essence, and Event snapshots, scoped NPC, and scoped hierarchical Region snapshots available. Live title feeds and APIs remain unconfirmed and intentionally unimplemented.
